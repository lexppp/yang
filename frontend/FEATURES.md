# 前端 UI v2：积分、邀请导出与 Lucky Draw

公告排期与全局英文输出见 [前端 v3](ANNOUNCEMENTS.md)。

此版本是可独立打开的前端交互演示，入口 `frontend/index.html`，需先创建本地超级管理员并登录，不依赖后端或 Bot Token。数据保存在浏览器，所有消息、用户、邀请和抽奖均为示例。`build_preview.py` 会打包全部样式、脚本与 XLSX 导出器，无 CDN 依赖。

## 积分

- 按社群、用户、北京时间自然月维护独立余额。每月 1 日 00:00（UTC+8）新月份余额为 0，上月余额不结转；不删除历史流水。
- 排行榜可选择月份。历史月份显示月末余额，仅可查看；流水保留签到、邀请、人工调整、抽奖消费等时间、数量、原因。
- 人工加减分只作用当前月，必须填写原因，扣后余额不能为负数。修改后可立即在流水中核对。
- 独立“积分设置”页面逐群配置签到和成功邀请积分，范围 0–10000，可设为 0。新规则仅影响后续行为，不回算过去记录。
- 测试机器人支持 `coinw`、`/ink`、模拟成功邀请、模拟链接拦截，可观察余额和邀请明细更新。

## 邀请 Excel

按所选社群和月份导出真正的 `.xlsx`，包含两张工作表：

1. 用户邀请汇总：月份、社群、邀请人 ID、昵称、用户名、邀请数量、最近成功入群时间、奖励积分。
2. 入群明细：月份、社群、邀请人及被邀请人 ID／昵称、入群时间（UTC+8）、单次计数 1、该次奖励积分。

按成功入群时间归属月份，不按邀请链接创建时间。历史月份也可导出。字段使用 OOXML 内联字符串，不执行用户输入的 Excel 公式。

## Lucky Draw

- 配置目标社群、活动名称、奖励内容、参与消耗积分、中奖人数，可上传不超过 1MB 的 PNG/JPG/WebP 图片；右侧实时预览公告。
- 状态：草稿 → 进行中 → 已开奖。保存草稿后，点击“发送并置顶（演示）”生成公告与置顶预览。
- 在公告中选择模拟成员参与，扣除其当前月余额；余额不足不能参与，每人每场一次，重复点击不重复扣分。无论是否中奖，参与消耗都不退回。
- 参与人数至少达到中奖人数后可手动开奖，使用浏览器安全随机源选择不重复用户。结果锁定且保存在本地，刷新不重抽。
- 中奖名单含昵称、Telegram 用户 ID、用户名及开奖时间；奖品需由运营核对发放。
- 抽奖可以跨月继续，已参与记录仍保留；跨月后新参与者使用新月份的可用积分，已参与者不能重复参加。

## 与真实系统的边界

本次新增功能仅在独立前端里实现。原 Python 后端 `app.py` 仍是第一版，不会从浏览器 localStorage 同步规则或积分。本版按钮不会真实发消息、置顶、批准入群或发放资产。后续关联 TG 时需实现相应服务器接口、数据库迁移、身份验证和管理员置顶权限校验，并以服务器事务保证扣分和参与去重；不能仅填写 Token 就将这份前端演示当作线上系统。

新前端模拟接口为 `/api/points/adjust`、`/api/draws/create`、`/api/draws/publish`、`/api/draws/enter`、`/api/draws/finish`。所有调用由本地适配器处理，无真实网络请求。


浏览器验收使用可选的 Playwright 和系统 Chromium，应用本身不依赖它们。覆盖真实浏览器操作、余额不足、重复参与、图片上传、规则生效、名单刷新保留，以及模拟北京时间月末跨界。导出文件通过 ZIP/OOXML 校验，并验证邀请汇总数量、奖励积分与明细一致。截图及示例 Excel 保存于忽略的 `data/frontend-v2/`。
