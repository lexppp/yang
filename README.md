# CoinW Community OS

Telegram 多社群管理机器人与中文管理看板。参考黑紫配色设计，提供社群设置、积分、邀请和日志。Python 3.12+ 标准库 + SQLite + 原生 HTML/CSS/JS，无需 npm 安装、Redis 或数据库服务。

## 当前交付：前端 UI v4

`frontend/index.html` 现需登录，支持首次创建超级管理员、普通管理员账号和功能授权，详见 [账号与权限说明](frontend/ACCOUNTS.md)。同时包含按月积分、人工调分、邀请 Excel、Lucky Draw，以及最新的图文公告、目标话题、定时/每日多时段、可选置顶和英文 TG 预览。详见 [积分与抽奖规则](frontend/FEATURES.md) 和 [公告与英文输出说明](frontend/ANNOUNCEMENTS.md)。**本次新增能力只在前端演示中实现，真实 TG 自动发送／置顶及新业务服务器接口尚未接入。** 下文的 Python 后端说明对应第一版，规则与 v2 存在差异。

## 先查看前端 UI（无需 Telegram）

直接用浏览器打开 `frontend/index.html`：单文件已内嵌样式、脚本和示例数据，首次创建本地超级管理员后登录，无需安装或启动后端。可体验社群筛选、欢迎词预览、规则保存、月榜／累计榜、邀请搜索与撤销、CSV 导出，以及“体验机器人”中的签到／邀请／链接拦截。所有数据均为演示；修改只保存在当前浏览器，不会操作真实社群。侧边栏可重置演示数据。

如果受管理浏览器禁止打开本地 HTML，可只启动静态文件服务（不是应用后端）：

```bash
python -m http.server 4173 --bind 127.0.0.1 --directory frontend
```

从前端源文件重新打包单文件：`python build_preview.py`。真实后端入口保持独立，已支持服务器账号和权限校验。

## 本地运行

```bash
cd /workspace/yang
python setup_local.py
python app.py
```

在自己的电脑部署时，浏览器打开所配置的主机和 8000 端口。云环境请使用平台支持的访问方式；当前引导界面不提供 localhost 预览。首次初始化超级管理员的账号为 `.env` 的 `ADMIN_USERNAME`（默认 `admin`），密码在 `ADMIN_PASSWORD`，请使用文件编辑器查看或修改，至少 12 位。生成器只在文件不存在时创建，权限为 0600，不打印密码、不覆盖已有配置。启动后读取 `.env`；修改环境配置须重启。启动时进程环境优先于 `.env`。

默认本地演示：4 个示例社群、签到积分和链接。演示链接以 `demo://` 开头，不可用于真实邀请。演示模式不会调用 Telegram，界面始终标注示例数据。没有默认公开密码。`.env`、数据库和运行产物均被 Git 忽略。

## 接入 Telegram

1. 在 Telegram 的 **@BotFather** 创建机器人，安全保存 Token。不要将 Token 发到聊天、提交到 Git 或写入公开日志。此程序需要能直接用于 Bot API 的运行时 Token；仅支持代理替换占位符的凭据注入方式须先确认与 Telegram URL 路径认证兼容。
2. 在私有 `.env` 设置 `TG_BOT_TOKEN`，将 `DEMO=0`，`DATABASE_PATH=data/community.sqlite3`。演示和生产数据库必须分开；程序阻止同一数据库切换模式。
3. 将机器人加入各个群，设为管理员，启用**删除消息**、**邀请成员／批准入群申请**权限。机器人收到权限事件后自动登记社群。无需复制群 ID。
4. 使用 @BotFather `/setprivacy` 禁用 Group Privacy，并按 Telegram 提示重新添加机器人。管理员机器人通常可接收群消息；仍需在群内验证普通文本 `coinw`、广告与编辑消息都能送达。
5. 本项目使用长轮询，仅运行一个实例。不需要公网 Webhook。若已有其他部署的 Webhook，程序暂停并提示；确认旧部署停用后，自行删除原 Webhook，再启动，程序不会擅自删除它。
6. 允许出站 HTTPS 到 `api.telegram.org`。不需要为长轮询暴露 HTTP 服务。
7. 重启后先检查看板顶部的连接状态与活动日志。在一个测试群完成下面的真实验收。

**启用入群验证的重要边界：** 本版通过 `/ink` 创建 `creates_join_request=true` 的群邀请链接，新成员申请后机器人向其私聊发送算术题，4 分钟内回答正确才批准。错误或过期会拒绝。撤销 Telegram 中其他直接入群链接，避免绕过验证；其他管理员直接添加或手动批准成员亦可绕过，日志会对观察到的直接入群发出提示。算术验证是基础拦截，不保证识别真人，也不阻止多 Telegram 账号刷邀请。

## 已实现的业务规则

- **社群设置**：每群独立英文欢迎文案，支持 `{name}`、`{group}`；欢迎图片使用 HTTPS URL 或 Telegram `file_id`，由 Telegram 下载。链接、图片和广告关键词拦截可单独开关。关键词以英文逗号分隔，匹配大小写不敏感。图片包括以文件发送的图片；管理员和匿名管理员消息豁免。编辑后的消息也会检查。图片、文案发送错误写入日志。
- **签到**：群内单独发送 `coinw`（不区分大小写），默认 +5 分。每群每人每北京时间自然日一次；数据库唯一约束避免并发重复发放。每天 00:00（UTC+8）重新开放领取，累计积分不清零。界面有倒计时；月榜按 UTC+8 自然月统计。积分即刻入账，无虚假的“待确认”队列。
- **邀请**：群内 `/ink` 或 `/ink@机器人用户名` 返回该群个人专属链接、实际邀请数和历史邀请积分。默认每次 +20 分。邀请入账发生在 Bot API 入群批准成功后；自己邀请自己、同一成员退群再加入、同一人改用别人的链接，均不重复奖励。未通过验证、仅打开链接不奖励。按群去重；已有群成员无法申请再次加入。邀请码使用 Telegram 实际群邀请链接，并非截图中的机器人 start 深链接；这使归因直接关联入群申请。
- **看板**：总览、单群筛选、规则编辑、月榜／累计榜（各前 50 名，跨群视图按“用户+群”分别排名）、邀请搜索和状态筛选、复制／撤销链接、最近 100 条活动日志、积分 CSV 导出。自动刷新间隔 15 秒。邀请表最多展示最新 500 条；成员表 API 最多返回 500 条。
- **统计口径**：成员数是机器人接入后观察到且未观察到离群的成员记录，不是 Telegram 全群人数，API 不提供完整历史成员列表。消息数从接入后累计，不代表历史消息。全群视图将各群人数相加，同一人在不同群会分别计入。
- **持久化**：SQLite WAL、事务和唯一约束；服务重启保留数据。积分规则变更仅作用于后续奖励，不回算历史。链接撤销需 Telegram 成功后本地才标记失效，保留历史积分。Webhook／网络／权限错误在顶部状态或日志展示。
- **登录安全**：管理密码 scrypt 校验；随机 HttpOnly、SameSite=Strict 会话，12 小时过期；CSRF、来源检查、登录失败限流、CSV 公式转义、页面文本转义。服务重启后须重新登录。已支持唯一超级管理员、普通管理员功能授权、持久化账号审计和会话撤销；尚无企业 SSO 或审计签名。

## 验证

```bash
python -m unittest discover -s tests -v
node --check static/app.js
```

单元／HTTP 集成测试用临时数据库和模拟 Telegram API，不使用真实 Token。覆盖并发签到、跨日、群隔离、邀请审批失败、过期验证、图片欢迎词、编辑消息拦截、鉴权、CSRF、设置与导出。

浏览器验收脚本 `tests/browser_smoke.py` 使用环境已有的 Playwright 和 Chromium（可选开发工具，非应用运行依赖），覆盖桌面／手机、登录、页面导航、设置保存、搜索及邀请撤销，截图输出到忽略的 `data/`。

真实验收须在测试群进行：

- 设置图文欢迎词，修改签到／邀请积分；验证新规则对后续事件生效。
- 普通成员同日发送两次 `coinw`，只入账一次；另一群可独立签到。
- 普通成员发送链接、隐藏链接、图片和匹配广告词；机器人应删除并记日志，管理员豁免。
- `/ink` 获取链接，由另一个非群成员申请，答题后入群；邀请人加分，看板同步。重入、错题、过期、自邀不应重复计分。
- 撤销链接后检查 Telegram 侧失效；重启服务检查持久化数据与重新登录。

## 部署与运行边界

应用入口 `python app.py` 同时启动 HTTP 看板和单个 Telegram 轮询线程。原型可直接运行，长期部署建议使用 systemd 或容器进程管理并在前方配置可信 HTTPS 反向代理。生产设置 `COOKIE_SECURE=1`，仅在需要时设置 `HOST=0.0.0.0`；不要直接将明文 HTTP 管理入口暴露到公网。HTTPS 代理需保留原 Host，前端同源调用。按可信代理 IP 限流需在代理层完成；应用不信任任意 X-Forwarded-For。

数据库默认在 `data/community.sqlite3`。使用 SQLite backup API 做在线一致备份，勿只复制正在使用的主文件而漏掉 WAL。日志包含用户 ID、邀请归因；请限制服务器和备份访问。

Python 后端第一版尚未实现截图里的抽奖（独立前端 v2 已提供演示）、UID 绑定、风险评分、多语言切换、人工加减积分、批量清空、广播功能。广告为规则匹配，无 AI 内容识别。Telegram 限流／网络故障会记日志，当前版本不提供可靠出站任务队列；处理失败的事件不会无限重放，通知、入群审批与数据库操作间也不存在跨服务原子事务。长期大规模运营前应补充任务队列、429 重试、告警、备份和真实压力测试。

云环境已自带隔离工作区，请复用现有检出；除非明确要求，不创建 Git worktree。
