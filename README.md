# CoinW Community OS

Telegram 多社群管理机器人与中文管理看板。参考黑紫配色设计，提供社群设置、积分、邀请和日志。Python 3.12+ 标准库 + SQLite + 原生 HTML/CSS/JS，无需 npm 安装、Redis 或数据库服务。

## 当前交付：前端 UI v4

`frontend/index.html` 现需登录，支持首次创建超级管理员、普通管理员账号和功能授权，详见 [账号与权限说明](frontend/ACCOUNTS.md)。同时包含按月积分、人工调分、邀请 Excel、Lucky Draw，以及最新的图文公告、目标话题、定时/每日多时段、可选置顶和英文 TG 预览。详见 [积分与抽奖规则](frontend/FEATURES.md) 和 [公告与英文输出说明](frontend/ANNOUNCEMENTS.md)。**独立单文件仍为演示。真实 Python 后端已支持群内入群验证，以及公告图文、话题、定时/每日多时段与置顶；积分月度清零、手动调分、邀请 Excel 和抽奖仍只在演示中实现。**

## 先查看前端 UI（无需 Telegram）

直接用浏览器打开 `frontend/index.html`：单文件已内嵌样式、脚本和示例数据，首次创建本地超级管理员后登录，无需安装或启动后端。可体验社群筛选、欢迎词预览、规则保存、月榜／累计榜、邀请搜索与撤销、CSV 导出，以及“体验机器人”中的签到／邀请／链接拦截。所有数据均为演示；修改只保存在当前浏览器，不会操作真实社群。侧边栏可重置演示数据。

如果受管理浏览器禁止打开本地 HTML，可只启动静态文件服务（不是应用后端）：

```bash
python -m http.server 4173 --bind 127.0.0.1 --directory frontend
```

从前端源文件重新打包单文件：`python build_preview.py`。真实后端入口保持独立，已支持服务器账号和权限校验。

## 接入 Telegram

1. 在 Telegram 的 **@BotFather** 创建机器人，安全保存 Token。不要将 Token 发到聊天、提交到 Git 或写入公开日志。此程序需要能直接用于 Bot API 的运行时 Token；仅支持代理替换占位符的凭据注入方式须先确认与 Telegram URL 路径认证兼容。
2. 在私有 `.env` 设置 `TG_BOT_TOKEN`，将 `DEMO=0`，`DATABASE_PATH=data/community.sqlite3`。演示和生产数据库必须分开；程序阻止同一数据库切换模式。
3. 将机器人加入各个群，设为管理员，启用**删除消息**、**邀请成员／批准入群申请**、**限制成员**权限；公告置顶还需**置顶消息**权限。机器人收到权限事件后自动登记社群。无需复制群 ID。
4. 使用 @BotFather `/setprivacy` 禁用 Group Privacy，并按 Telegram 提示重新添加机器人。管理员机器人通常可接收群消息；仍需在群内验证普通文本 `coinw`、广告与编辑消息都能送达。
5. 本项目使用长轮询，仅运行一个实例。不需要公网 Webhook。若已有其他部署的 Webhook，程序暂停并提示；确认旧部署停用后，自行删除原 Webhook，再启动，程序不会擅自删除它。
6. 允许出站 HTTPS 到 `api.telegram.org`。不需要为长轮询暴露 HTTP 服务。
7. 重启后先检查看板顶部的连接状态与活动日志。在一个测试群完成下面的真实验收。

**群内入群验证：** 新成员入群后先禁言，群内显示算术按钮，答对后恢复群默认发言权限。后台设置消息保留1–1440分钟；超时删验证消息，用户保持禁言，不踢出。需要超级群及限制成员/删除消息权限，管理员跳过验证。新个人邀请链接采用申请制，由机器人自动批准后转群内验证，无需私聊。欢迎词兼容成员状态和新成员服务消息，并去重；图片失败时回退文字。算术验证仅为基础拦截，不保证识别真人。

## 已实现的业务规则

- **社群设置**：每群独立英文欢迎文案，支持 `{name}`、`{group}`；欢迎图片使用 HTTPS URL 或 Telegram `file_id`，由 Telegram 下载。链接、图片和广告关键词拦截可单独开关。关键词以英文逗号分隔，匹配大小写不敏感。图片包括以文件发送的图片；管理员和匿名管理员消息豁免。编辑后的消息也会检查。图片、文案发送错误写入日志。
- **签到**：群内单独发送 `coinw`（不区分大小写），默认 +5 分。每群每人每北京时间自然日一次；数据库唯一约束避免并发重复发放。每天 00:00（UTC+8）重新开放领取，累计积分不清零。界面有倒计时；月榜按 UTC+8 自然月统计。积分即刻入账，无虚假的“待确认”队列。
- **邀请**：群内 `/link` 或 `/link@机器人用户名` 返回该群个人专属链接、实际邀请数和历史邀请积分。默认每次 +20 分。开启验证时，邀请入账发生在群内验证成功后；关闭验证时入群后入账；自己邀请自己、同一成员退群再加入、同一人改用别人的链接，均不重复奖励。未通过验证、仅打开链接不奖励。按群去重；已有群成员无法申请再次加入。邀请码使用 Telegram 实际群邀请链接，并非截图中的机器人 start 深链接；归因使用 Telegram 入群申请或成员事件中的邀请链接。旧直入链接保留，但再次发送 /link 会生成新的申请制链接，以便在批准前记录邀请来源。
- **欢迎图片 ID**：私聊机器人发送照片，或回复照片发送 `/fileid`，获取可粘贴到欢迎图片字段的 `file_id`。图片需按「照片」发送；按「文件」发送的图片会收到重发提示，群内图片不会自动回显 ID。机器人无需下载图片。
- **公告**：服务器持久化图文和目标话题，支持立即发送、定时一次、每日1–24个时段、可选置顶、暂停和取消。时间为UTC+8；超过5分钟的错过时段不补发，发送不确定时不自动重发，记录消息ID和置顶结果。话题从机器人收到的消息中发现，也支持手填ID。
- **看板**：总览、单群筛选、规则编辑、月榜／累计榜（各前 50 名，跨群视图按“用户+群”分别排名）、邀请搜索和状态筛选、复制／撤销链接、最近 100 条活动日志、积分 CSV 导出。自动刷新间隔 15 秒。邀请表最多展示最新 500 条；成员表 API 最多返回 500 条。
- **统计口径**：成员数是机器人接入后观察到且未观察到离群的成员记录，不是 Telegram 全群人数，API 不提供完整历史成员列表。消息数从接入后累计，不代表历史消息。全群视图将各群人数相加，同一人在不同群会分别计入。
- **持久化**：SQLite WAL、事务和唯一约束；服务重启保留数据。积分规则变更仅作用于后续奖励，不回算历史。链接撤销需 Telegram 成功后本地才标记失效，保留历史积分。Webhook／网络／权限错误在顶部状态或日志展示。
- **登录安全**：管理密码 scrypt 校验；随机 HttpOnly、SameSite=Strict 会话，12 小时过期；CSRF、来源检查、登录失败限流、CSV 公式转义、页面文本转义。服务重启后须重新登录。已支持唯一超级管理员、普通管理员功能授权、持久化账号审计和会话撤销；尚无企业 SSO 或审计签名。

真实验收须在测试群进行：

- 设置图文欢迎词，修改签到／邀请积分；验证新规则对后续事件生效。
- 普通成员同日发送两次 `coinw`，只入账一次；另一群可独立签到。
- 普通成员发送链接、隐藏链接、图片和匹配广告词；机器人应删除并记日志，管理员豁免。
- `/link` 获取链接，由另一个非群成员加入，在群内答题解除禁言；邀请人加分，看板同步。重入、错题、过期、自邀不应重复计分。
- 撤销链接后检查 Telegram 侧失效；重启服务检查持久化数据与重新登录。

## 部署与运行边界

应用入口 `python app.py` 同时启动 HTTP 看板和单个 Telegram 轮询线程。原型可直接运行，长期部署建议使用 systemd 或容器进程管理并在前方配置可信 HTTPS 反向代理。生产设置 `COOKIE_SECURE=1`，仅在需要时设置 `HOST=0.0.0.0`；不要直接将明文 HTTP 管理入口暴露到公网。HTTPS 代理需保留原 Host，前端同源调用。按可信代理 IP 限流需在代理层完成；应用不信任任意 X-Forwarded-For。

数据库默认在 `data/community.sqlite3`。使用 SQLite backup API 做在线一致备份，勿只复制正在使用的主文件而漏掉 WAL。日志包含用户 ID、邀请归因；请限制服务器和备份访问。

Python 后端第一版尚未实现截图里的抽奖（独立前端 v2 已提供演示）、UID 绑定、风险评分、多语言切换、人工加减积分、批量清空功能。公告发布已实现，仍需真实测试群验收。广告为规则匹配，无 AI 内容识别。Telegram 限流／网络故障会记日志，当前版本不提供可靠出站任务队列；处理失败的事件不会无限重放，通知、入群审批与数据库操作间也不存在跨服务原子事务。长期大规模运营前应补充任务队列、429 重试、告警、备份和真实压力测试。

云环境已自带隔离工作区，请复用现有检出；除非明确要求，不创建 Git worktree。


### 邀请诊断与社群连接

邀请管理中的“入群与邀请归因”显示已观察到的入群、验证及入账状态。仅点击链接不计数；普通群升级为超级群时，仅凭 Telegram 提供的升级映射合并群 ID 和历史数据，不按同名猜测。已保存来源且验证成功的遗漏记录自动补记；没有来源的记录由具备“补记邀请（含积分奖励）”权限的管理员核实后，选择邀请人、填写依据并确认，操作记入日志且不重复发奖。

社群列表的“解除连接”需要单独的“解除与恢复社群连接”权限。默认保留机器人在 Telegram 中的身份，但停止后台处理并隐藏社群、暂停定时公告，保留历史数据；可明确勾选让机器人同时退群。待验证成员不会因此自动解除禁言，需人工处理。页面上方“已解除社群”可恢复连接，恢复前检查机器人管理员身份；公告保持暂停，需另行恢复。群收到新消息不会自行恢复已解除的连接。

新增验收：`PYTHONPATH=tests:. python tests/group_links_browser_smoke.py`，模拟 Telegram 验证归因补记、权限边界、解除与恢复及手机布局，不调用真实 Telegram。


### 欢迎语与邀请链接消息自动清理

真实后台将自己发送的欢迎语（含图片）和 `/link`、兼容 `/ink` 的链接回复登记为持久化删除任务。默认欢迎语4分钟、链接回复2分钟；社群设置可分别设0–1440分钟，0表示保留。修改只对之后发送的消息生效，已有任务继续按发送时的时间执行。验证按钮使用独立的验证超时，不删除用户命令、签到回复或公告，也不撤销邀请链接或积分。

清理任务在服务启动后继续执行；网络/权限错误按退避重试，并遵守 Telegram 的 retry_after，首个失败和最终失败记入活动日志。已手动删除的消息视为清理完成。Telegram 超过48小时的消息不再尝试删除，永久不可删除和重试耗尽记录失败，需管理员处理。解除社群连接会取消其清理任务；群升级时保留原始聊天ID和消息ID，不把旧消息编号错误套用到新群。

旧版本未存储已发送欢迎语和链接回复的消息ID，更新无法从 Bot API 枚举并补删这些历史消息；管理员需手动清理。新功能验收覆盖文字/图片/失败回退、管理员/免验证成员、重启续期、失败重试、限流、跨群隔离、解除连接、权限与设置保存。


### 加强反广告与每群权限检查

真实后端使用 `moderation.py` 的确定性规则，不调用AI或消耗模型Token。新增普通成员的按钮外链、未在白名单的@用户名/成员提及、转发和外部频道身份拦截，以及账号/KYC买卖、代收款、高收益招揽话术识别。规范化全角文字、大小写和部分不可见字符，关键词支持中英文逗号、分号与换行。普通市场讨论与KYC问题不按这些词本身封禁。图片内文字未做OCR；规则可能误判，可按群关闭相应规则或调整关键词与提及白名单。

社群设置的“应用推荐防广告设置”开启链接/关键词/提及/按钮/转发/频道身份/重复文本/刷屏检查，保存后生效，不覆盖欢迎词、图片、积分和原关键词。@白名单支持账号名和 `id:数字ID`，不等于授予管理员权限。默认同一成员10秒内第9条消息、10分钟内第3条相同长文本开始拦截；编辑消息也检查，但同一消息不重复累计违规。默认首次删除，24小时内第2条违规起禁言1440分钟，不踢人；违规阈值1–10、禁言0–10080分钟，0仅删除。

真实Telegram管理员、匿名群管理员、关联频道自动转发豁免；普通用户借外部频道身份发布仍可拦截，不对Telegram合成匿名用户ID禁言。限制操作执行前重新检查管理员身份，不缩短已有更严格禁言；已过期的延迟禁言任务取消，避免Telegram将不足30秒的限制变成永久禁言。

删除和禁言任务写入SQLite，失败退避重试并遵守限流，重启续跑；可在活动日志看命中原因、消息ID、待重试/最终失败。成员权限查询失败的疑似广告也留待重试，执行前保护管理员。每群“检查机器人权限”显示实际管理员、删除、限制成员权限及待处理数，需要 `groups.manage`；所有新设置也受该权限保护。解除连接或升级群时取消旧群待处理任务，不把旧消息ID套用新群。

只保护已经接入且机器人是管理员的群。Telegram先接收消息再通知机器人，删帖可能短暂可见，不保证绝对零广告；不能通过Bot API遍历所有历史消息，历史广告需人工清理。其他机器人主动发送的消息可能不会送达本机器人；普通用户通过内联机器人发送、带 `via_bot` 的消息仍按收到的消息检查。入群验证不是完整的反广告系统，同群避免多个机器人同时控制入群禁言/解禁。
